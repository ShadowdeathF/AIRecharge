# 采购、企业对账与分成验收记录

## 已执行验证

- Maven 全量 `package`：106 项测试，0 失败、0 错误；包括原有订单/工作台回归、公司协议价与结账、采购精确分摊、原单累计追补、季度权重、退款负余额，以及两个并发测试。
- 前端全部现有及新增 Node 测试：24 项通过。TypeScript `--noEmit` 和 Next.js 生产构建通过。
- 在原有 1,725 笔订单的本地 PostgreSQL 副本执行五个 SQL 迁移，使用 Hibernate `validate` 启动成功。副本中的旧订单原数量保留，无法追溯采购的旧库存保持成本未知。
- Chrome 实际操作：月度采购 3 份/300.01 元入库；企业 120 元协议价录入、实际收款、采购出库成本与确认；20 元利润结算计入经营预留 2 元和无推荐人分红预留 2.70 元。
- 三个新增后台入口在 1440/390 宽度、亮色/暗色中检查，无页面横向溢出、浏览器运行错误或 HTTP 500；已目视核对截图。
- 前台浏览器验证企业 A 的 120 元商品/购物车价格，退出登录后忽略延迟私有报价并恢复公开价，切换到企业 B 后更新为 110 元。
- PostgreSQL API 验证：推荐人追补后保留原归属并展示当前归属；已付后退款产生个人负余额，部分退回款减少负余额；公司支出实际流水跨表单去重；采购与模拟卡密入库原子重试；并发争用最后一份库存仅一笔成功；后续调整后原结算 CSV 仍可导出。

## 独立审查与修复

独立审查发现的七项重要问题已修复：平台来源绑定去重、确认前金额/归属更正、默认人员待确认、公司支出实际流水去重、人员付款/退回明细回查、当前推荐归属派生、确认时计提经营预留及区间报表。针对修复复核未发现新的重复计提、重复出库或原单金额覆盖。

复核提出的平台关联表单静默忽略推荐人问题，已通过关联模式禁用这些字段、后端/CSV 明确拒绝覆盖输入解决。首次确认人员前不能生成正式结算。

真实历史数据检查还发现整批同步占用财务锁过久，已改为每请求最多 50 笔、分批提交和逐批刷新，增加 51 笔订单的分批回归。

## 范围

上述为本地源代码、数据库副本及浏览器验证。实际供应商采购、真实支付/退款/转账、外部支付回调和公网服务器更新不包含在本轮验收结果中。所有验收卡密均为明确标记的本地模拟内容。
